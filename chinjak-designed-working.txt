15. Availability API

This is now connected to the frontend.

Endpoint:

GET /chinjak-api/availability

Parameters:

checkIn
checkOut
adults
children

Example:

/chinjak-api/availability?checkIn=2026-10-15&checkOut=2026-10-17&adults=2&children=0

The backend validates:

date format
real calendar dates
check-out after check-in
adults > 0
children >= 0
room capacity

It also checks physical room availability against existing bookings.

Booking overlap logic:

b.status IN ('PENDING', 'CONFIRMED', 'CHECKED_IN')
AND b.check_in < requested_check_out
AND b.check_out > requested_check_in

This prevents overlapping reservations.

39. Important Current Business Rules

These should be remembered before changing backend logic.

Availability

A physical room is unavailable when an active booking overlaps the requested dates.

Active blocking statuses:

PENDING
CONFIRMED
CHECKED_IN

Cancelled bookings do not block rooms.

Booking

Currently:

One booking
→ one room

Multi-room booking is not implemented yet.

Payment

Currently:

UNPAID

There is no payment gateway yet.

Tax

Currently:

0

No tax calculation has been implemented yet.

Pending bookings

A PENDING booking currently blocks the assigned room.

Later we may want an expiration/holding mechanism so abandoned bookings don't block inventory indefinitely.
